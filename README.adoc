[IMPORTANT]
.Not to be confused with AffineScript
====
This is **Ephapax**, a research language for WebAssembly memory safety.
It is *not* https://github.com/hyperpolymath/affinescript[AffineScript], a
separate language at `hyperpolymath/affinescript` that succeeds JS / TS /
AffineScript.

The two share **exactly one thing**: both target
https://github.com/hyperpolymath/typed-wasm[typed-wasm]. They have separate
ASTs, separate type checkers, separate compilers, separate proof stories.
The word `affine` overlaps in both names because it names a substructural-
logic property — that's a logic-family fact, not a project relationship.

Internal note: Ephapax is itself dyadic — `ephapax-linear` (strict core)
and `ephapax-affine` (versatile prototyping companion) are *both inside this
repo*, one Rust crate, one AST, two structural disciplines. **`ephapax-affine`
is not AffineScript.** When ambiguous, write "ephapax-affine sublanguage"
vs "AffineScript language".

Canonical disambiguation (read this before applying any cross-repo
lesson):
link:https://github.com/hyperpolymath/nextgen-languages/blob/main/docs/disambiguation/ephapax-vs-affinescript.md[nextgen-languages/docs/disambiguation/ephapax-vs-affinescript.md].
====

[NOTE]
.🌱 Ephapax is gestating — second-draft in progress; proof redesign required (start with `V1-TO-V2.adoc`)
====
This language is in a deliberate second-draft process. Grammar work is
active; the proof track has preserved a false legacy theorem and discovered
further L1/L2 gaps that require redesign. The full status is in
link:V1-TO-V2.adoc[`V1-TO-V2.adoc`] and `PROOF-NEEDS.adoc`.

**The grammar (v1 → v2).** The flat v1 surface worked for the core but
could not grow into modules / generics / effects / comptime. v2 adds the
missing layer — *surface → desugar → core* — and is **landing in phases,
tests green** (`spec/ephapax-v2-grammar.ebnf` + the `v2_grammar_phase_*`
suite).

**The soundness proof (v1 → v2).** On 2026-05-26 a machine-checked Coq
counterexample (link:formal/Counterexample.v[`formal/Counterexample.v`],
then 5 Qed lemmas, now 6 with `preservation_false`) *proved* that preservation as stated in the legacy
single-judgment design is unsound — a region exit could invalidate a
sibling's assumptions untracked. Discovering that **with a proof, before
anyone depended on it**, is the rare correct thing, not a failure. The four-layer architecture is a design program, not an established
preservation result. The legacy statement is retired to
`preservation_stmt : Prop` and refuted by `Counterexample.preservation_false`;
the no-False gate rejects any `Admitted`, so it must not be restored. Later
pinned counterexamples also refute the unrestricted L1 preservation claim.
There is no unconditional L2 preservation theorem, while the L2 β-case
helpers are conditional. L3's `preservation_l3` and case lemmas are Qed
for matching echo-emitting rule pairs only; L4 is a Phase A scaffold.

**For anyone (human or bot) doing the work:** preserve every pinned
counterexample and do not attempt to prove a refuted statement. Active proof
work means specifying and proving sound replacements locally for Ephapax's
own syntax, judgments, and steps—not relying on shared vocabulary or an
upstream repository.

Ephapax is a research language for **principled handling of
irreversible boundaries** (region exits, drops, key erasure, audit
trails) in compile-time-memory-safe WebAssembly. Real systems are
irreversible — operating systems deallocate, databases drop tables,
security systems erase keys, compilers collapse high-level
distinctions. Ephapax is designed to track not just *what is owned* but *what was
lost when it was given up*, so reclamation can carry evidence where it
matters and degrade where it does not. This is a research design goal,
not a claim that all language-level soundness obligations are proved.

The core has Coq and Idris2 formal artifacts, but the current Coq
preservation story is incomplete and has pinned counterexamples: legacy
preservation and the unrestricted L1 statement are false as stated, and
no unconditional L2 theorem is established. See the proof ledger and
`PROOF-NEEDS.adoc` before interpreting any local lemma as a language-wide
guarantee.

== Why "Ephapax"?

The Greek _ἐφάπαξ_ ("ephapax") means **once for all**. It evokes the
linear-typing design goal: track each linear resource so it is consumed
exactly once. The intended guarantee must still be established for
Ephapax's judgments, implementation, and operational semantics; current
preservation counterexamples show that this is not automatic.

== What this is

Ephapax is a programming language with:

[cols="1,3"]
|===
| Property | What this means

| **Dyadic discipline (L2)**
| Each binding is *either* affine (`let` — used at most once,
  weakening allowed) *or* linear (`let!` — used exactly once,
  weakening forbidden). Type checker enforces. See "The four layers"
  below for how this composes with L1/L3/L4.

| **Region-based memory (L1)**
| Allocations are designed around named regions (`region r: ...`). The
  L1 judgment threads a region-capability environment, but current
  unrestricted L1 preservation is refuted by pinned Coq counterexamples;
  sibling safety is a design goal, not an established guarantee. When a
  region's scope ends, the runtime bulk-frees resources in it; this
  implementation behavior is not proved to refine the calculus.

| **Second-class borrows**
| `&x` gives temporary access without consuming `x`. Borrows cannot
  be stored, escape their introduction scope, or be used after the
  borrowed resource is freed.

| **Compile-time memory safety (design target)**
| The intended goal is to reject use-after-free, double-free, and leaks
  of linear resources before code generation. General preservation and
  implementation refinement are not established; see `PROOF-NEEDS.adoc`.

| **WebAssembly target**
| `wasm32-unknown-unknown` primary; native via Cranelift secondary.

| **No GC, no allocator runtime**
| Region exits do the bulk deallocation. No tracing collector, no
  reference counting, no allocator-per-object metadata.
|===

== The four layers

Ephapax's design separates four disciplines. Their composition and
soundness are proof obligations, not an automatic consequence of
orthogonality or of a related repository's theory. `echo-types` is a
conceptual reference; Ephapax-local claims require Ephapax-local proofs.

[cols="1,3"]
|===
| Layer | What it enforces

| **L1 — Region capabilities**
| Region environments are threaded through compound typing rules. This
  is intended to prevent stale sibling references, but the current
  preservation statement is refuted as stated by pinned L1 counterexamples;
  it is not a proved language guarantee. See `PROOF-NEEDS.adoc`.

| **L2 — Structural discipline (linear ↔ affine)**
| The *modality* of the surrounding program decides whether linear
  bindings must be consumed (Linear: ephapax-linear) or may be dropped
  (Affine: ephapax-affine). Same syntax, same semantics — different
  admissible derivations. Linear ⊆ Affine, proved by `linear_to_affine`
  Qed in `formal/Modality.v`.

| **L3 — Irreversibility residue (Echo)**
| Operations that erase information (region exit, drop) produce
  proof-relevant residue — `Echo f y := Σ A (λ x → f x ≡ y)`. In
  Linear mode the residue must be observed; in Affine mode it may be
  silently lowered. Calculus mechanised in `formal/Echo.v`;
  integration into the typing judgment is the next-block work.

| **L4 — Dyadic interaction mode**
| A project-level declaration of which side of the dyad the program
  speaks from (`ephapax_linear` / `ephapax_affine` /
  `module_boundary_mix`). Selects the L2 modality and the L3
  observation discipline. No proof obligations of its own — mechanical
  scaffold in `formal/L4.v` carries definitions only by design.
|===

.Soundness story
****
The four-layer separation is a design response to the verified legacy
counterexample (`formal/Counterexample.v`), not itself a soundness proof.
Later pinned regressions refute the current unrestricted L1 preservation
statement, and no unconditional L2 preservation theorem is established.
Making invariants explicit is necessary design work, but every Ephapax
typing/step combination still requires a local theorem with proven
assumptions. See `PROOF-NEEDS.adoc` for the current boundary.
****

== Three superpowers

The L3 echo / residue layer (Ephapax's contribution to the four-layer
design) opens three things proper reversible programming struggles
with:

[cols="1,3"]
|===
| Superpower | What it gives you

| **A. Accountability of irreversible reclamation**
| The design aims to make irreversible events (`S_Region_Exit`,
  `S_Drop`) carry typed evidence under Linear discipline, with a more
  permissive Affine path. This is a design intent; the local L1/L2
  preservation gaps mean it is not yet an end-to-end proved guarantee.

| **B. Selective reversibility (thin-poset)**
| Linear ≤ Affine is a two-point thin poset at the L2 modality. You
  pick per-region (or per-project) which discipline applies. Same
  code shape, different evidence obligations. Concrete examples:
  *Linear* during backpropagation (must keep the gradient residue);
  *Affine* during inference (drop the residue, save memory). These are
  design examples; their safety properties require local proofs and are
  not established by the modality poset alone.

| **C. Debugging + provenance**
| The design uses Linear Echoes to require receipts (preimages) for
  selected state changes and permits opting out in Affine mode. The
  intended guarantee is that evidence is retained, but current preservation
  gaps mean this must not be described as a proved end-to-end language
  guarantee yet.
|===

[CAUTION]
.Echo Types are NOT a tracing-GC replacement
====
Echo Types do **not** solve reachability or cycles. They are not a
"fire-and-forget" automatic memory manager. Their strength is
*accountability of irreversible reclamation* in systems that already
know when and how to deallocate (regions, explicit drop, deterministic
ownership). Treating them as competition for mark-and-sweep or
generational GC is a category error.

The committed v1 direction is *Linear Echo + Region-Based Memory
Management* (deterministic bulk free with mandatory certified
evidence). A speculative future direction is an optional Linear
discipline on deterministic Rust-style drop for critical resources
(keys, sensitive buffers requiring provable erasure) — flagged but
not committed.
====

== Design targets and use cases

These are intended applications of the design, not currently established
end-to-end language guarantees. Any particular safety claim needs a proved
Ephapax theorem with its exact assumptions and implementation boundary.

* **Mandatory evidence for critical actions (design target).** A future
  Linear-echo discipline is intended to require observation of selected
  region exits or drops. The current L3 Qed lemmas cover matching rule
  pairs only; they do not establish this end-to-end guarantee.

* **GDPR "right to be forgotten" with certified evidence of erasure
  (potential application).** The design explores making deletion evidence
  explicit. No current Ephapax theorem proves erasure, notification, or
  logging for personal-data programs.

* **Resource management for keys, secrets, and sensitive buffers
  (potential application).** The design aims to make selected deallocation
  events auditable; it does not currently prove physical erasure or
  implementation refinement.

* **Selective reversibility.** The Linear/Affine modality is mechanised,
  and the Echo calculus has a local non-invertibility result. These
  isolated facts do not prove the proposed system composes soundly or
  provides end-to-end guarantees.

* **Potential foundation for policy enforcement.** Any compliance claim
  requires a precisely scoped Ephapax theorem and an implementation
  boundary; cross-repository Echo results and conceptual vocabulary do
  not discharge those obligations.

== What this isn't

* **Not Rust.** Rust uses ownership + borrowing with a single discipline
  (affine-ish, with linearisation via `Drop`). Ephapax separates the
  two disciplines explicitly: `let` is affine, `let!` is linear, and
  the user chooses per-binding.
* **Not a research vapourware.** 17 active Rust workspace crates + `tests/fuzz` (with `src/ephapax-tools/` outside the workspace and `src/ephapax-vram-cache/` explicitly disabled — needs `hyperpolymath/ephapax-proven`); the lexer,
  parser, interpreter, REPL, CLI, S-expression IR, two-phase pipeline,
  Zig FFI, and conformance test suite are complete. Type checker and
  WASM codegen are in progress. See `ROADMAP.adoc`.
* **Not yet self-hosting.** The compiler is written in Rust. The
  formalisation is in Coq + Idris2. Self-hosting is a v1.0+ goal.

== Hello, world

[source,ephapax]
----
fn main() -> i32 {
    let x = 1 + 2;
    let y = x * 3;
    y
}
----

A region with linear strings:

[source,ephapax]
----
region r:
    let s1 = String.new@r("hello, ")
    let s2 = String.new@r("world")

    -- Borrow s1 to get length (does not consume)
    let len = String.len(&s1)

    -- Concatenation consumes both strings
    let result = String.concat(s1, s2)

    -- result is consumed by being returned
    result
-- Region exits: any remaining allocations bulk-freed.
----

A linear binding (must consume):

[source,ephapax]
----
fn process(input: i32) -> i32 {
    let! z = copy(input) in
    z + 1  -- z is consumed exactly once
}
----

More examples in `examples/` and `conformance/valid/`.

== Formal foundations

The type system is grounded in:

* **Intuitionistic linear logic** — resource-sensitive reasoning
* **Separation logic** — memory ownership and framing
* **Tofte-Talpin region calculus** — scoped allocation

Two complementary formalisations, both run on every push:

=== Coq (`formal/`)

Operational semantics with small-step reduction over a substitution-
based calculus. Post-2026-05-26 the formalisation is layered:

* **Legacy** (`formal/Semantics.v`, `formal/Typing.v`) — the original
  pre-discovery judgment. Its preservation statement is **provably
  false**: it is now `preservation_stmt : Prop`, refuted by
  `Counterexample.preservation_false` (Qed). The former `Admitted.` was
  retired on 2026-11-05 (owner-ratified D0/D0b). **Do not extend.**
  Treat as archaeology — see link:STATUS.adoc[`STATUS.adoc`] for the
  pre-discovery PR list and the explicit do-not-do reasoning.

* **Layer 1 — region capabilities** (`formal/TypingL1.v`,
  `formal/Semantics_L1.v`). The modality-indexed judgment threads a
  capability environment `R`. The judgment and helper lemmas are
  mechanised, but the unrestricted `preservation_l1` statement is
  refuted by `Counterexample_PreservationL1.v`; its supporting
  `step_pop_disjoint_from_type_l1` statement is separately refuted by
  `Counterexample_StepPop.v`. Both are retired to `Prop` statements
  (`preservation_l1_stmt`, `step_pop_disjoint_from_type_l1_stmt`; D0,
  2026-11-05) and are not proof debt. A sound replacement requires a
  judgment/step redesign and an explicit theorem boundary. See
  `PROOF-NEEDS.adoc`.

* **Layer 2 — structural modality** (`formal/Modality.v`). Linear
  vs Affine as a K-free thin-poset decoration. `linear_to_affine`
  is **Qed with zero axioms**. Landed via PRs #176 + #177.

* **Layer 3 — echo / residue** (`formal/Echo.v`). 12 Qed lemmas
  covering the fiber calculus, degrade map, and the
  `no-section-collapse-to-residue` irreversibility theorem (mirrors
  the upstream Agda development at
  https://github.com/hyperpolymath/echo-types[`hyperpolymath/echo-types`]).
  Wiring into the L1 typing rules landed via slice 4 (2026-05-27):
  `preservation_l3_region_active_echo`, `preservation_l3_drop_echo`,
  and the `preservation_l3` umbrella are Qed for their matching echo
  rule pairs; they do not establish general L1/L2 preservation.

* **Layer 4 — dyadic interaction**. Phase A scaffold landed
  2026-05-28: `formal/L4.v` defines `ProgramMode`
  (`PModeLinear` / `PModeAffine` / `PModeBoundaryMix`) and the
  `program_mode_to_modality` round-trip. No theorems by design
  (definitions only — labelling discipline, not a proof layer). Design
  in link:formal/PRESERVATION-DESIGN.adoc[`formal/PRESERVATION-DESIGN.adoc §7`].

Per-sublanguage proof debt with explicit do-not-do list lives in
link:PROOF-NEEDS.adoc[`PROOF-NEEDS.adoc`]. The four-layer architecture
rationale is in
link:formal/PRESERVATION-DESIGN.adoc[`formal/PRESERVATION-DESIGN.adoc`].
The counterexample itself is
link:formal/Counterexample.v[`formal/Counterexample.v`] (6 Qed, including `preservation_false`).

=== Idris2 (`idris2/src/Ephapax/` + `src/formal/`)

Two Idris2 developments:

* **`idris2/src/Ephapax/`** — the actual frontend (parser, type

== Surface syntax (locked)

[source]
----
// Function declaration
fn main() -> i32 {
    let x = 1 + 2;
    let y = x * 3;
    y
}

// Linear binding
let! z = copy(x) in z

// Region scope
region r:
    let s = String.new@r("data")
    String.len(&s)
----

Grammar highlights:

* Functions: `fn name(params) -> Ty { ... }` or `fn name(params) : Ty { ... }`
* Affine bindings: `let x = expr in expr`
* Linear bindings: `let! x = expr in expr`
* Block expressions: `{ expr1; expr2; …; exprN }` (final expr is the result)
* Newlines are statement separators (equivalent to `;`)
* Comments: `//` and `--` to end-of-line

Full grammar: `spec/ephapax-spec.md`. The v2 grammar work (modules,
generics, effects, traits, comptime, contracts) lives on
`feat/v2-grammar-cross-module` branches; see GitHub PRs for status.

== Seam analysis

Key interfaces where correctness and stability matter:

* Idris2 → S-expression IR (`Ephapax.IR.Decode` encoding/decoding)
* Zig FFI token buffer → Idris2 parser stream (`Ephapax.Parse.ZigBuffer`)
* S-expression IR → Rust/WASM backend (`ephapax-ir` and `ephapax-wasm`)
* Surface AST → Core AST (`ephapax-desugar` — proofs target core only)

The `proven` library is a dependency so string-handling paths over
the IR boundary harden over time (JSON-style escaping, etc.).

== Contributing

Contributions welcome. Please see:

* link:.github/CONTRIBUTING.md[.github/CONTRIBUTING.md] — getting started
* link:CODE_OF_CONDUCT.adoc[CODE_OF_CONDUCT.adoc] — community standards

The highest-leverage open work, in priority order:

1. **L1/L2 soundness redesign** — specify judgment and operational
   invariants that reject the pinned counterexamples, then state and prove
   replacement preservation theorems with explicit hypotheses. Existing
   Phase 3b work is conditional infrastructure, not an unconditional
   L2 theorem.
2. **Progress for redesigned judgments** — state and prove progress and
   canonical forms only against the final redesigned judgments. Do not
   combine these with the refuted unrestricted `preservation_l1` claim to
   assert conventional type soundness.
3. **Fuel-refactor `Parse/Parser.idr`** from `%default covering` to
   `%default total`. Substantial — ~30 mutually-recursive combinators
   threaded through a `Stream` record.
4. **Type-checker completion** (`ephapax-typing`) and **WASM codegen
   for lambda/app** (`ephapax-wasm`).
5. **Native backend via Cranelift** (v0.2.0).

[NOTE]
====
*Proving the legacy preservation statement in `formal/Semantics.v` is
NOT a valid contribution.* It is provably false: it is retired to
`preservation_stmt : Prop` and refuted by `Counterexample.preservation_false`
(owner directive 2026-05-27; retirement owner-ratified as D0/D0b on
2026-11-05). `formal/PRESERVATION-HANDOFF.adoc` is
archaeology kept for context. The redesigned judgments are a separate development, not yet a sound
replacement: `preservation_l1` is refuted as stated, and no unconditional
`preservation_l2` theorem exists. L2 β-case lemmas have explicit
preconditions; L3 results cover only matching echo rule pairs. The active
work is to specify and prove sound replacement theorems without weakening
the pinned regressions. See `formal/PRESERVATION-DESIGN.adoc` and
`PROOF-NEEDS.adoc`.
