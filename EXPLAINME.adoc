= Ephapax — Show Me The Receipts
:toc:
:toclevels: 3
:icons: font

The README makes claims. This file backs them up — every assertion in
README.adoc is tied to a specific file, test, or proof obligation.

[quote, README]
____
A research language for principled handling of irreversible boundaries
in WebAssembly. Ephapax aims to track resource use and typed evidence at
region exits and drops. Its local preservation obligations remain under
proof: the legacy theorem and current unrestricted L1 theorem are refuted,
and no unconditional L2 preservation theorem is established.
____

== Claim: Dyadic Type System (L2)

The dyad is L2 in the four-layer architecture (see
`README.adoc#the-four-layers` and `docs/vision/EPHAPAX-VISION.adoc`).
This section presents the Rust-side evidence for the L2 discipline;
L1 / L3 / L4 evidence follows below.

*Evidence*: The type checker (`src/ephapax-typing/src/lib.rs`) tracks
`BindingForm` per context entry:

* `BindingForm::Let` -- affine discipline, `demands_consumption()` returns `false`
* `BindingForm::LetBang` -- linear discipline, `demands_consumption()` returns `true`
* `BindingForm::Param` -- follows type linearity

Tests `test_let_allows_unconsumed_linear` and `test_let_bang_rejects_unconsumed`
exercise the distinction. `test_let_bang_rejects_unconsumed_unrestricted` checks
that this implementation rejects `let!` without consumption for unrestricted
types like `I32`. These are behavioral tests, not a proof of language soundness
or compiler refinement.

The Coq-side L2 evidence is `linear_to_affine : Linear ≤ Affine` (Qed,
zero axioms) in `formal/Modality.v`.

== Claim: Two-Layer AST (Surface + Core)

*Evidence*: Two separate crates:

* `src/ephapax-surface/` -- Surface AST with `DataDecl`, `Match`, `Construct`, `Pattern`, `SurfaceTy::Named`
* `src/ephapax-syntax/` -- Core AST with binary sums, `case`/`inl`/`inr`
* `src/ephapax-desugar/` -- Transforms surface to core

The Coq formal artifacts (`formal/`) reason about the core AST only. Surface
features such as pattern matching and named constructors are not part of those
proofs. The desugar/type-check test below exercises the implementation, but no
formal preservation theorem currently connects the surface pipeline to the
Coq calculus.

Test `integration_desugar_typecheck_no_parser` in `ephapax-desugar` exercises the
pipeline: surface AST -> desugar -> core AST -> type check.

== Claim: Pattern Matching Desugars to Binary Sums

*Evidence*: `src/ephapax-desugar/src/lib.rs` implements:

* `data Option(a) = None | Some(a)` -> type `() + a` (right-nested binary sums)
* `None` -> `inl(())`, `Some(x)` -> `inr(x)` (constructor injection chains)
* `match ... of` -> nested `case`/`inl`/`inr` (case tree generation)

Tests: `desugar_option_i32`, `desugar_color_green`, `desugar_color_blue`,
`desugar_match_color` (verifies nested case for 3-variant match),
`desugar_non_exhaustive_match` (rejects incomplete patterns).

== Claim: Dual Substructural Grammars

*Evidence*: `ephapax-linear/` contains two EBNF grammar specifications:

* `grammar/linear.ebnf` -- no weakening, no contraction, branch agreement required
* `grammar/affine.ebnf` -- weakening OK, no contraction, branches may disagree

`LinearChecker` and `AffineChecker` in Rust enforce these grammars. 14 tests
demonstrate where they diverge on identical programs (e.g.
`linear_rejects_unconsumed_let_bang` vs `affine_allows_unconsumed_let`).

== Claim: Region-Based Memory

*Implementation evidence*: `check_region` in `src/ephapax-typing/src/lib.rs`
checks that the return type does not reference the region and that bindings
marked `demands_consumption()` are consumed at region exit. The tests
`test_region_non_escaping` and `test_region_string_allocation` exercise this
checker behavior. These tests do not establish a theorem connecting the Rust
checker or runtime to the Coq calculus.

== Claim: Region capability threading (L1; soundness boundary open)

*Evidence*: `has_type_l1` threads region environments through compound
rules in `formal/TypingL1.v`. This is the redesign's intended capability
accounting, but the current judgment does **not** establish that a region
used by a surviving sibling remains live across another sibling's step.

* `formal/Counterexample.v` contains five Qed lemmas. Three prove the
  legacy witness types, steps, and becomes untypable; the L1 regression
  proves only that this particular input is rejected in both modes.
* `formal/Counterexample_StepPop.v` refutes the unrestricted
  `step_pop_disjoint_from_type_l1` statement.
* `formal/Counterexample_PreservationL1.v` refutes the
  modality-polymorphic `preservation_l1` statement through its Linear
  instance. It does not establish that a separate Affine-only statement
  is false.
* The local proof artifacts are Coq evidence only. The exact open
  replacement boundary and Grade 3 policy are in `PROOF-NEEDS.adoc`.

== Claim: Irreversibility residue is first-class (L3, wired)

*Design*: The L3 calculus models typed residues for selected irreversible
operations, drawing on the `echo-types` formulation. This does not establish
that all runtime region exits/drops emit or discharge residue; the local Qed
preservation results are scoped to the matching rules listed below.

* Upstream theory at
  `~/developer/repos/echo-types/proofs/agda/EchoLinear.agda` (lines
  30–101), already mechanised.
* Local mirror at `formal/Echo.v` — the L3 calculus is mechanised
  here (modes, `LEcho`, `weaken`, `degrade_mode`, all `Qed`).
* Forward-looking design at `formal/PRESERVATION-DESIGN.adoc §6`.
* Status: **wiring landed** (slice 4, 2026-05-27).
  `preservation_l3_region_active_echo`, `preservation_l3_drop_echo`,
  and the `preservation_l3` umbrella in `Semantics_L1.v` are Qed for
  their matching echo-emitting rule pairs. These scoped results do not
  establish general L1/L2 preservation.

== Claim: Dyadic mode is project-level only (L4)

*Evidence*: L4 is a labelling discipline, not a proof layer.
`formal/L4.v` carries `ProgramMode` (three-constructor enum) and
`program_mode_to_modality` (total mapping to L2's modality). No
theorems, no admits, no axioms — by design.

* Companion design note: `formal/L4-DYADIC.adoc`.
* Canonical design source: `formal/PRESERVATION-DESIGN.adoc §7`.
* Surface syntax for the L4 declaration
  (`#![ephapax_linear]` / `#![ephapax_affine]` /
  `#![module_boundary_mix(...)]`) is not yet wired into the parser
  or borrow checker; the mechanical scaffold is a citable type for
  downstream tools (Idris2 ABI, Rust borrow checker, surface
  parser).

=== Coq (`formal/`)

[IMPORTANT]
.Post-counterexample 2026-05-26 — read this before any older proof claim
====
The legacy preservation theorem in `formal/Semantics.v` is **provably
false**. `formal/Counterexample.v` (5 Qed lemmas) demonstrates a
configuration that types under the legacy judgment, steps via the
operational semantics, and lands at an untypable post-state. The
`Admitted.` on `Theorem preservation` is correct — no proof closes it.

The post-discovery architecture is a design program, not yet a sound
replacement. The unrestricted L1 preservation statement is refuted by
`Counterexample_PreservationL1.v`; L2 has no unconditional preservation
theorem, and its counterexamples constrain the β-case helpers. L3's Qed
results are scoped to matching echo rules. Any earlier-in-this-README
counts of "910 → 22 → 12 open goals" are archaeology, not instructions.
See `STATUS.adoc` and `PROOF-NEEDS.adoc` for current boundaries.
====

The Coq formalisation has layered judgments and infrastructure, but
not a soundness theorem for every layer. L1's unrestricted preservation

zero axioms), the L1 judgment and helper lemmas, the L3 calculus and
scoped matching-rule preservation results, the L4 Phase A scaffold
(definitions only), and pinned counterexample regressions. What's open =
redesign the L1 judgment/step interface and state sound replacement
theorems; L2 has no unconditional preservation theorem and its β-case
helpers remain conditional. What's banned = trying to prove the false
legacy or current unrestricted L1 statements, masking counterexamples,
adding new `Axiom` declarations, or conflating `ephapax-affine` (this
repo's sublanguage) with `AffineScript` (a separate language at
`hyperpolymath/affinescript`). Full boundary in `PROOF-NEEDS.adoc`.
