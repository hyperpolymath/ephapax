== Proof Debt — ephapax

=== Current enforced inventory (2026-11-09)

This section is the current inventory consumed by the trusted-base gate. The
older closure plan below is retained only as labelled archaeology. A path being
listed here means that its trust boundary is documented; it does *not* mean the
obligation has been discharged.

==== Coq (`+formal/+`): no escape hatches

Since the owner-ratified D0/D0b change of 2026-11-05 (ephapax#422), no file in
`+formal/_CoqProject+` contains `+Admitted+`, `+admit+`, `+Axiom+`,
`+Parameter+`, `+Conjecture+`, a top-level `+Hypothesis+`/`+Variable+`, or a
kernel-check bypass. `+formal/scripts/no-false-gate.sh+` enforces this in CI
(`+coq-build.yml+`): a comment-aware token scan, a `+Print Assumptions+` census
of every named result (each must be closed under the global context), and an
independent `+coqchk+` recheck of the compiled libraries. Its census on
2026-11-09 found 446 of 446 named results closed (every theorem-class
result and every `+Definition+`, `+Fixpoint+` and `+CoFixpoint+`; the earlier
tally of 299 counted theorem-class results only), including the P2
regression families in `+formal/regress/+`. `+coqchk+` lists
`+Coq.Logic.Eqdep.Eq_rect_eq.eq_rect_eq+` among the axioms of the *loaded
standard library*; the census shows no Ephapax result depends on it.

The three statements that used to carry `+Admitted+` are false as stated. They
are kept as `+Prop+` definitions so their refutations can be stated, and they
are not debt:

* `+Semantics.preservation_stmt+` (legacy preservation) is refuted by
  `+Counterexample.preservation_false : ~ preservation_stmt+`.
* `+Semantics_L1.step_pop_disjoint_from_type_l1_stmt+` is refuted by
  `+Counterexample_StepPop.step_pop_disjoint_from_type_l1_FALSE+`: a typed
  step can remove a region still free in the result type.
* `+Semantics_L1.preservation_l1_stmt+` is refuted by
  `+Counterexample_PreservationL1.preservation_l1_FALSE+`: an input typed in
  both modalities steps to a post-state untypable in the Linear instance. This
  does not by itself refute a separate Affine-only theorem.

The counterexamples are proof regressions, not proofs of an alternative
soundness theorem. The open work is to redesign or strengthen the judgment /
operational interface with an explicit temporal liveness/coherence invariant,
then state and prove a replacement theorem with its exact boundary.

==== L2 preservation boundary — `+formal/TypingL2.v+`

There is no unconditional theorem named `+preservation_l2+` in the current
tree. `+preservation_l2_via_l1+` takes `+Semantics_L1.preservation_l1_stmt+`
as an explicit hypothesis, which `+preservation_l1_FALSE+` refutes, so it
proves nothing unconditionally. The β-case lemmas are proved only under their
stated preconditions. `+formal/Counterexample_L2.v+` (fresh-region scope
crossing) and `+formal/Counterexample_L2_nested.v+` (nested `+TFunEff+`
lambda) record distinct counterexample classes for broader L2
β-preservation. They do not invalidate the conditional helper lemmas whose
hypotheses exclude those classes; nor do they establish full L2
preservation. Any future L2 theorem must name and prove its restricted
boundary without inheriting the L1 counterexample by assumption.

==== Idris2 ABI seam (`+src/abi/+`): 12 erased postulates

* *Status*: `ASSUMED`. Twelve top-level `+0 name : …+` declarations have no
  clauses: `+typePreservation+`, `+linearConsumptionAcrossControlFlow+`,
  `+ReferencesRegion+`, `+regionNoRuntimeEscape+`, `+noRuntimeGC+`,
  `+WasmTyped+`, `+compile+`, `+wasmCompilationPreservesTyping+`, `+SStep+`,
  `+lowerIR+`, `+irLoweringPreservesSemantics+` (all in
  `+src/abi/Ephapax/ABI/Invariants.idr+`) and `+compileOkImpliesWasmTyped+`
  (`+src/abi/Ephapax/ABI/Foreign.idr+`). Idris2 0.8.0 accepts such a
  declaration as a postulate even under `+%default total+`; a test module
  with `+0 bad : Void+` proves `+1 = 2+` with no warning (checked
  2026-11-09).
* *Consistency*: reading `+WellTyped+` and `+Step+` as empty (they have no
  constructors) makes every postulated proposition vacuously true, and the
  postulated types and functions are abstract constants over inhabited
  types. So the set is consistent, and for the same reason it asserts
  nothing about Ephapax. E1 (`+typePreservation+`) is refuted for the
  legacy judgment by `+Counterexample.preservation_false+`; the obligation
  moves to the v2 judgment.
* *Build*: `+idris2 --build ephapax-abi.ipkg+` and
  `+idris2 --build ephapax-formal.ipkg+` exit 0 with Idris2 0.8.0
  (2026-11-09). `+src/formal/+` has no undefined declarations.
* *Detection*: textual escape-hatch scans that look only for `+believe_me+`
  or `+assert_total+` miss these. The mathesis census scanner reports them
  as `+undefined declaration+` axiom candidates (hyperpolymath/mathesis#27).

==== `+idris2/src/Main.idr:22+` — global `+%default partial+`

* *Status*: real module-wide Idris2 totality waiver; configured and compiled,
  but neither totality-audited nor proved.
* *Scope*: the affine front-end executable, including argument parsing, file
  I/O orchestration, parser invocation, type checking, and emission.
* *Owner*: @hyperpolymath.
* *Plan and tracking*: issue #380. Audit each definition under
  `+%default total+`; keep any unavoidable partiality narrowly attached to the
  smallest I/O boundary with a stated precondition and failure result. This is
  part of the Idris2 ABI trust boundary, so a global waiver is not an acceptable
  final state.
* *Acceptance*: a negative control demonstrates that Idris2 rejects a deliberately
  non-total pure definition; the module builds under total-by-default checking;
  every remaining local `+partial+` is individually documented and gated.

=== Rust/Creusot verification boundary

Ephapax contains proof-critical Rust but currently has no Creusot integration,
contracts, reproducible solver setup, or hard verification gate. Issue #378 is
the canonical closure record. Rust tests, Coq bridge tests, and typed-Wasm checks
are valuable evidence, but they do not imply that Creusot obligations were
generated or discharged. Until #378 is completed with its required failing
positive control, the Rust implementation is *tested, not Creusot-proved*.
